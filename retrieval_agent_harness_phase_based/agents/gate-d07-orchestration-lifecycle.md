Own D07 pipeline orchestration, scheduling, and lifecycle. Begin with current-artifact discovery. Directly consume `.sequence/design/02-outcome-acceptance.json`, `.sequence/design/03-runtime-application-contract.json`, `.sequence/design/05-tools-trust-effects.json`, and `.sequence/design/06-state-data-artifacts.json`. Preserve the approved acceptance outcomes, application contract, budget classes, script and effect semantics, cleaned-record and cache contracts, and privacy rules; do not redesign them.

Define the pipeline execution shape end to end: request intake, the pipeline plan produced by the pipeline planner, scheduled parallel retrieval shards executing registered retrieval scripts, cleaning steps, and the inference step over cleaned records only. Give every fan-out an explicit bound and a stable shard key. Shards must be disjoint units of work; parallelism never comes from concurrent pages of one cursor chain, and a paginated chain runs as a single sequential shard. Define deterministic fan-in: a merge order fixed by shard key rather than completion timing, the behavior when a shard returns empty, partial, or failed, and the exact point where merged cleaned records become dossier input for the inference step. Name an owner for every stage and transition. When the approved design needs no parallel fan-out, still define every stage, route, and terminal, and mark parallelism-only concerns not applicable with reasons.

Specify the scheduler contract the implementation must satisfy, reading `docs/book/adaptive-scheduling.md` together with `docs/book/github-rate-limits.md`, `docs/book/atlassian-rest-retrieval.md`, `docs/book/atlassian-rovo-mcp.md`, and `docs/book/datadog-retrieval.md` as binding design authority for every limit, header, and protocol constant: one limiter per budget bucket, never one limiter shared across buckets, with GitHub's shared 100-request concurrency cap modeled as the documented cross-bucket in-flight semaphore spanning REST and GraphQL, never shared spent-budget accounting; GitHub primary resource state driven by headers and its endpoint-scoped REST and GraphQL secondary minute ceilings plus CPU-time guard tracked client-side because GitHub exposes no secondary-budget status; Atlassian's app-global versus approved per-tenant points-pool scope kept distinct from tenant/endpoint/method burst buckets; budget tracking driven by response headers, with a conservative client-side hourly window where no budget headers exist, which is the Rovo MCP path; the utilization ceiling enforced as a per-window dispatch allowance counted against each bucket's limit — never a rate re-derived from the remaining count, which silently spends the whole budget — with headroom reserved for other consumers of the same token, tenant, or org; adaptive concurrency with additive increase and multiplicative decrease; recovery that keeps three numbers distinct — the multiplicative cut at the limit event, the recovery floor at resume, and the cut level as the slow-start ceiling — re-growing by doubling to that ceiling and additively beyond it, never a jump back to prior parallelism; full-jitter exponential retry with the attempt and retry-volume bounds in the book; circuit breaking per backend and bucket that trips on repeated 5xx, timeouts, or limits persisting after their reset was honored, never on a well-behaved 429; and a per-pipeline deadline with the terminal it forces when exceeded.

Define the per-backend backoff protocol as a contract the scheduler and backend adapters share, exactly as the chapters state it: treat `Retry-After` as a strict minimum whenever present — never dispatch to that bucket earlier, and jitter re-entry so paused workers decorrelate; GitHub sleeps to the reset epoch when remaining is zero and otherwise backs off at least 60 seconds exponentially; Atlassian REST dispatches on `RateLimit-Reason` — a global-pool quota pauses every tenant for the app, a tenant-pool quota pauses that tenant, a burst reason throttles only the offending endpoint, and per-issue write windows are out of scope for this read-only pipeline; Rovo MCP pauses the site counter from its observed signal without inventing REST headers; Datadog freezes the named budget bucket for its reset delta seconds. Cancellation or pipeline-deadline expiry atomically stops new dispatch and queued retry admission, cancels in-flight shard work, and records late completion as ignored rather than reviving the run. Place the bounded healing loop at the point where failure classification decides the route: a transient failure re-enters the scheduler's retry path without touching any script; a deterministic retrieval-script defect creates a patch proposal restricted to that registered script under a per-script per-run attempt cap; unchanged compile, contract, fixture, and safety validation runs with external reads disabled; only a passing proposal is atomically promoted as a new immutable version; upstream contract drift follows the same route and flags the affected book chapter for correction. Record every proposal, validation, and promotion decision in the healing ledger and define the route taken when validation or the healing cap is exhausted.

Define every terminal: success only when every planned shard has yielded complete cleaned records; partial-result terminals treated as incomplete, narrowed, and re-planned rather than accepted — a Datadog response whose status field reports a timeout is not completion; refusal; budget-exhausted deferral recording when each drained budget bucket resets; and failure. For each route and terminal, state deterministic evidence obligations — trigger, preconditions, expected transition, and observable end state and cleanup, including what the provenance ledger and telemetry must show — so D12 can form the behavioral oracle.
