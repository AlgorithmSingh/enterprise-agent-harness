Own D07 pipeline orchestration, scheduling, and lifecycle. Begin with current-artifact discovery. Directly consume `.sequence/design/02-outcome-acceptance.json`, `.sequence/design/03-runtime-application-contract.json`, `.sequence/design/05-tools-trust-effects.json`, and `.sequence/design/06-state-data-artifacts.json`. Preserve the approved acceptance outcomes, application contract, budget classes, script and effect semantics, cleaned-record and cache contracts, and privacy rules; do not redesign them.

Define the pipeline execution shape end to end: request intake, the pipeline plan produced by the pipeline planner, scheduled parallel retrieval shards executing registered retrieval scripts, cleaning steps, and the inference step over cleaned records only. Give every fan-out an explicit bound and a stable shard key. Shards must be disjoint units of work; parallelism never comes from concurrent pages of one cursor chain, and a paginated chain runs as a single sequential shard. Define deterministic fan-in: a merge order fixed by shard key rather than completion timing, the behavior when a shard returns empty, partial, or failed, and the exact point where merged cleaned records become dossier input for the inference step. Name an owner for every stage and transition. When the approved design needs no parallel fan-out, still define every stage, route, and terminal, and mark parallelism-only concerns not applicable with reasons.

Specify the scheduler contract the implementation must satisfy, reading `docs/book/adaptive-scheduling.md` together with `docs/book/github-rate-limits.md`, `docs/book/atlassian-rest-retrieval.md`, `docs/book/atlassian-rovo-mcp.md`, and `docs/book/datadog-retrieval.md` as binding design authority for every limit, header, and protocol constant: one limiter per budget bucket, never one limiter shared across buckets, with GitHub's shared 100-request concurrency cap modeled as the single documented cross-bucket coupling — an in-flight semaphore spanning REST and GraphQL, never shared spent-budget accounting; budget tracking driven by response headers, with client-side counting per site per hour where no budget headers exist, which is the Rovo MCP path; the utilization ceiling enforced as a per-window dispatch allowance counted against each bucket's limit — never a rate re-derived from the remaining count, which silently spends the whole budget — with headroom reserved for other consumers of the same token, tenant, or org; adaptive concurrency with additive increase and multiplicative decrease; recovery that keeps three numbers distinct — the multiplicative cut at the limit event, the recovery floor at resume, and the cut level as the slow-start ceiling — re-growing by doubling to that ceiling and additively beyond it, never a jump back to prior parallelism; full-jitter exponential retry with a bounded attempt count; circuit breaking per backend and bucket that trips on repeated 5xx, timeouts, or limits persisting after their reset was honored, never on a well-behaved 429; and a per-pipeline deadline with the terminal it forces when exceeded.

Define the per-backend backoff protocol as a contract the scheduler and backend adapters share, exactly as the chapters state it: treat `Retry-After` as a strict minimum whenever present — never dispatch to that bucket earlier, and jitter the release so paused workers decorrelate; GitHub sleeps to the reset epoch when remaining is zero and otherwise backs off at least 60 seconds exponentially; Atlassian dispatches on `RateLimit-Reason` — a quota reason pauses the whole product until the UTC-hour reset, a burst reason throttles only the offending endpoint, and per-issue write windows are out of scope for this read-only pipeline; Datadog freezes the named budget bucket for its reset delta seconds. Place the bounded healing loop at the point where failure classification decides the route: a transient failure re-enters the scheduler's retry path without touching any script; a deterministic retrieval-script defect routes to healing under a per-script per-run attempt cap with a healing-ledger entry for every attempt; upstream contract drift heals the script and flags the affected book chapter for correction in the same route. Define the route taken when the healing cap is exhausted.

Define every terminal: success only when every planned shard has yielded complete cleaned records; partial-result terminals treated as incomplete, narrowed, and re-planned rather than accepted — a Datadog response whose status field reports a timeout is not completion; refusal; budget-exhausted deferral recording when each drained budget bucket resets; and failure. For each route and terminal, state deterministic evidence obligations — trigger, preconditions, expected transition, and observable end state and cleanup, including what the provenance ledger and telemetry must show — so D12 can form the behavioral oracle. Do not write tests, choose test files, run tests, or claim they passed.

Write only `.sequence/design/07-orchestration-lifecycle.json`, with sections covering the pipeline execution shape and sharding rules, fan-in ordering, the scheduler contract, the per-backend backoff protocol, healing routes and caps, terminals, and per-route evidence obligations. Leave Python module and symbol naming to D09 and D10, and test selection to D12 and the build gates.
