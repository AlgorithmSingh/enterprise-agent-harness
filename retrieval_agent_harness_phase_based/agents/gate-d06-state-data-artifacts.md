Own D06 state, cache, cleaned-data contracts, and privacy. Begin with current-artifact discovery. Directly consume `.sequence/design/01-repository-intake.json`, `.sequence/design/02-outcome-acceptance.json`, `.sequence/design/03-runtime-application-contract.json`, and `.sequence/design/05-tools-trust-effects.json` for repository facts, required outcomes, the pipeline application contract, and the approved backend adapters, budget buckets, and effect semantics. Read `docs/book/github-rate-limits.md`, `docs/book/gh-cli-retrieval.md`, `docs/book/atlassian-rest-retrieval.md`, `docs/book/atlassian-rovo-mcp.md`, and `docs/book/datadog-retrieval.md` as binding design authority for every cache, cursor, header, and lifetime constant this artifact states; do not assert a number those chapters do not support.

Define the script registry layout and versioning: where each retrieval script lives, its stable identity and version, the typed parameters and declared budget class recorded with it, how the current version is resolved for a run, and how healing produces a proposal restricted to that script. Promotion must occur only after unchanged compile, contract, recorded-fixture, and safety checks pass with external reads disabled; it atomically installs an immutable new version while the prior version remains current and inspectable on any failure. Design the retrieval cache as distinct classes: per-URL conditional-request revalidation state holding ETag and Last-Modified where the backend makes revalidated 304s free; TTL classes separating immutable data such as commits and closed issues from live data such as monitor states and open work; and cached discovery results such as the Atlassian `cloudId`. Every cached response copy has an approved byte bound and an oversize disposition. Cache keys must include token identity where the governing chapter requires it — the gh on-disk cache keys on the Authorization header and retains cached 404s for the full TTL — so state whether each script wraps that cache or the system owns its own, and how a stale or poisoned entry is purged.

Persist pagination cursors as first-class state with documented lifetimes: an Atlassian `nextPageToken` expires in 7 days and is valid only with the same query and fields, so store it with that identity and a captured-at time and treat expiry as restart-the-scan, not an error; Datadog cursors are strictly sequential state — page N+1 exists only in page N's response — valid only with the identical query and absolute time bounds; a Confluence scan ends when `_links.next` is absent, which is normal termination, not a lost cursor. Define the cleaned-record schema contract: the minimal field set each request class needs, a schema version, deterministic serialization, and mandatory provenance on every record — source, query, retrieval time, and budget spent — so any cleaned record traces back to the script invocation and bucket charge that produced it.

Define the dossier layout for a pipeline run: where the pipeline plan, cleaned records, provenance ledger, budget telemetry, and run outcome live, and what the inference step may read — cleaned records and their provenance only, never raw payloads or cache internals. The provenance ledger records every script invocation with its parameters, bucket charges, and produced records; the healing ledger records script identity and version, failure classification, the exact diff applied, attempt count, and outcome. It also distinguishes proposed from applied diffs and records old/new version hashes, bounded redacted diagnostic or structural-schema evidence, unchanged validation results, and the promotion decision for every proposal. Raw provider values are not healer input. Budget telemetry records planned versus actual spend per bucket using exactly the bucket identities D05 approved, never an aggregate that merges buckets. Set retention and cleanup rules per class: cache entries expire by TTL, cursors are deleted at expiry or scan completion, dossiers and ledgers are append-only with an explicit retention horizon, and recorded fixtures kept for the cleaning step's tests are redacted before retention. Where parallel shards share cache, cursor, counter, or ledger state — including the client-side counters that are the only view of the Rovo budget — require single-writer ownership or atomic append with no lost updates. Credential presence is a recordable fact; a credential value in any cache entry, cursor record, dossier, ledger, fixture, or telemetry line is a defect. The same is true of a credential value in a healer prompt or diagnostic; captured URLs, headers, stdout, stderr, and exception text must be bounded and redacted accordingly.
